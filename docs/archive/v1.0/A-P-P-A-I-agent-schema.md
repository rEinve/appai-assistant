## 2. Background Data Architecture Overview

The A-P-P-A-I microservice engine relies on a multi-tier data architecture engineered for relational transactional integrity, sub-second governance evaluation, and event-driven decoupling.

*   **Relational Persistent Store (PostgreSQL 16)**: Serves as the primary source of truth for user governance profiles, order intent lifecycles, catalog matches, scoped payment tokens, and financial transaction logs with strict ACID guarantees.
*   **In-Memory State Cache (Redis 7.2)**: Provides sub-millisecond atomic accumulators for daily user spending caps, distributed redlocks for checkout synchronization, and short-lived Human-in-the-Loop approval session states.
*   **Event Streaming Bus (Apache Kafka / Redis Streams)**: Facilitates asynchronous inter-service communication between the Catalog Discovery Engine, Governance Guardrails Engine, and Tokenized Payment Execution Rail.
*   **Immutable Audit Ledger**: An append-only, cryptographically signed log table to guarantee security compliance and full operational auditability.

## 3. Relational Database Schema (PostgreSQL 16 DDL)

### 3.1 User Governance & Profile Entity (`users_governance`)

Stores user account identification, hard spending caps (`max_item_price_cap`, `daily_spend_cap`), daily spend accumulators, and Human-in-the-Loop escalation thresholds.

```sql
CREATE TABLE users_governance (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) NOT NULL UNIQUE,
    full_name VARCHAR(128) NOT NULL,
    max_item_price_cap DECIMAL(10,2) NOT NULL DEFAULT 50.00 CHECK (max_item_price_cap > 0),
    daily_spend_cap DECIMAL(10,2) NOT NULL DEFAULT 200.00 CHECK (daily_spend_cap >= max_item_price_cap),
    current_daily_spend DECIMAL(10,2) NOT NULL DEFAULT 0.00 CHECK (current_daily_spend >= 0),
    hitl_escalation_threshold DECIMAL(10,2) NOT NULL DEFAULT 100.00 CHECK (hitl_escalation_threshold > 0),
    currency CHAR(3) NOT NULL DEFAULT 'USD',
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_gov_email ON users_governance(email);
```

### 3.2 Merchant Catalog Registry Entity (`merchant_catalogs`)

Maintains connected merchant profiles, Model Context Protocol (MCP) server endpoints, JSON-LD feed locations, and integration trust scores.

```sql
CREATE TABLE merchant_catalogs (
    merchant_id VARCHAR(64) PRIMARY KEY,
    merchant_name VARCHAR(128) NOT NULL,
    mcp_endpoint_url VARCHAR(512) NULLABLE,
    json_ld_feed_url VARCHAR(512) NULLABLE,
    integration_type VARCHAR(32) NOT NULL CHECK (integration_type IN ('MCP_SERVER', 'JSON_LD_FEED', 'HYBRID_API')),
    trust_score DECIMAL(3,2) NOT NULL DEFAULT 1.00 CHECK (trust_score BETWEEN 0.00 AND 1.00),
    is_enabled BOOLEAN NOT NULL DEFAULT TRUE,
    last_health_check TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_merchants_active ON merchant_catalogs(is_enabled, trust_score);
```

### 3.3 Procurement Intent Entity (`order_intents`)

Captures natural-language user queries, extracted NLP metadata, user ceiling prices, and lifecycle state flags.

```sql
CREATE TYPE intent_status_enum AS ENUM (
    'PARSED', 
    'SEARCHING', 
    'MATCHED', 
    'GOVERNANCE_CHECK', 
    'GOVERNANCE_PASSED', 
    'GOVERNANCE_BLOCKED', 
    'HITL_PENDING', 
    'HITL_APPROVED', 
    'HITL_REJECTED', 
    'TOKEN_REQUESTED', 
    'TOKEN_ISSUED', 
    'CHECKOUT_SUBMITTED', 
    'COMPLETED', 
    'FAILED'
);

CREATE TABLE order_intents (
    intent_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users_governance(user_id) ON DELETE RESTRICT,
    raw_prompt TEXT NOT NULL,
    parsed_category VARCHAR(128) NOT NULL,
    extracted_keywords JSONB NOT NULL DEFAULT '[]'::jsonb,
    extracted_max_price DECIMAL(10,2) NOT NULL CHECK (extracted_max_price > 0),
    required_delivery_date DATE NULLABLE,
    status intent_status_enum NOT NULL DEFAULT 'PARSED',
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_intents_user_status ON order_intents(user_id, status);
CREATE INDEX idx_intents_created ON order_intents(created_at DESC);
```

### 3.4 Catalog Match Entity (`catalog_matches`)

Stores product candidates retrieved by the Catalog Discovery Engine from MCP or JSON-LD feeds for a given procurement intent.

```sql
CREATE TABLE catalog_matches (
    match_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    intent_id UUID NOT NULL REFERENCES order_intents(intent_id) ON DELETE CASCADE,
    merchant_id VARCHAR(64) NOT NULL REFERENCES merchant_catalogs(merchant_id),
    product_sku VARCHAR(128) NOT NULL,
    product_title VARCHAR(256) NOT NULL,
    item_price DECIMAL(10,2) NOT NULL CHECK (item_price >= 0),
    shipping_cost DECIMAL(10,2) NOT NULL DEFAULT 0.00 CHECK (shipping_cost >= 0),
    total_amount DECIMAL(10,2) GENERATED ALWAYS AS (item_price + shipping_cost) STORED,
    currency CHAR(3) NOT NULL DEFAULT 'USD',
    in_stock BOOLEAN NOT NULL DEFAULT TRUE,
    estimated_delivery TIMESTAMP WITH TIME ZONE NOT NULL,
    raw_feed_payload JSONB NOT NULL,
    selected_for_checkout BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_matches_intent ON catalog_matches(intent_id, selected_for_checkout);
```

### 3.5 Human-in-the-Loop Escalation Entity (`hitl_escalations`)

Manages governance policy exceptions, budget threshold breaches, and user approval tokens.

```sql
CREATE TYPE escalation_status_enum AS ENUM ('PENDING', 'APPROVED', 'REJECTED', 'EXPIRED');

CREATE TABLE hitl_escalations (
    escalation_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    intent_id UUID NOT NULL REFERENCES order_intents(intent_id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users_governance(user_id),
    match_id UUID NOT NULL REFERENCES catalog_matches(match_id),
    trigger_reason VARCHAR(128) NOT NULL,
    exceeded_amount DECIMAL(10,2) NOT NULL,
    approval_token_hash VARCHAR(256) NOT NULL UNIQUE,
    status escalation_status_enum NOT NULL DEFAULT 'PENDING',
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
    decided_at TIMESTAMP WITH TIME ZONE NULLABLE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_hitl_user_pending ON hitl_escalations(user_id, status) WHERE status = 'PENDING';
```

### 3.6 Scoped Payment Token Entity (`payment_tokens`)

Tracks single-use or merchant-restricted tokens generated via PayPal Agent Ready endpoints. Raw payment card credentials are never ingested or stored.

```sql
CREATE TYPE token_status_enum AS ENUM ('ISSUED', 'CONSUMED', 'EXPIRED', 'REVOKED');

CREATE TABLE payment_tokens (
    token_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    intent_id UUID NOT NULL REFERENCES order_intents(intent_id),
    user_id UUID NOT NULL REFERENCES users_governance(user_id),
    merchant_id VARCHAR(64) NOT NULL REFERENCES merchant_catalogs(merchant_id),
    payment_token_ref_hash VARCHAR(256) NOT NULL UNIQUE,
    max_authorized_amount DECIMAL(10,2) NOT NULL,
    currency CHAR(3) NOT NULL DEFAULT 'USD',
    status token_status_enum NOT NULL DEFAULT 'ISSUED',
    issued_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
    consumed_at TIMESTAMP WITH TIME ZONE NULLABLE
);

CREATE INDEX idx_tokens_ref ON payment_tokens(payment_token_ref_hash);
CREATE INDEX idx_tokens_status ON payment_tokens(status);
```

### 3.7 Transaction Audit Log Entity (`transaction_logs`)

Maintains an immutable record of all merchant native API checkout attempts, execution latencies, and confirmation IDs.

```sql
CREATE TYPE transaction_status_enum AS ENUM ('SUCCESS', 'DECLINED', 'API_ERROR', 'TIMEOUT');

CREATE TABLE transaction_logs (
    transaction_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    intent_id UUID NOT NULL REFERENCES order_intents(intent_id),
    user_id UUID NOT NULL REFERENCES users_governance(user_id),
    token_id UUID NOT NULL REFERENCES payment_tokens(token_id),
    merchant_id VARCHAR(64) NOT NULL REFERENCES merchant_catalogs(merchant_id),
    product_sku VARCHAR(128) NOT NULL,
    final_amount DECIMAL(10,2) NOT NULL,
    currency CHAR(3) NOT NULL DEFAULT 'USD',
    merchant_order_id VARCHAR(128) NULLABLE,
    status transaction_status_enum NOT NULL,
    execution_latency_ms INTEGER NOT NULL,
    raw_response_payload JSONB NULLABLE,
    executed_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_tx_user_date ON transaction_logs(user_id, executed_at DESC);
CREATE INDEX idx_tx_status ON transaction_logs(status);
```

### 3.8 Cryptographic Audit Event Ledger (`audit_events`)

Partitioned append-only audit ledger providing tamper-evident cryptographic tracking for compliance verification.

```sql
CREATE TABLE audit_events (
    audit_id BIGSERIAL PRIMARY KEY,
    event_uuid UUID NOT NULL DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,
    intent_id UUID NULLABLE,
    event_type VARCHAR(64) NOT NULL,
    event_severity VARCHAR(16) NOT NULL CHECK (event_severity IN ('INFO', 'WARN', 'CRITICAL')),
    payload JSONB NOT NULL,
    cryptographic_signature VARCHAR(256) NOT NULL,
    logged_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_audit_user_time ON audit_events(user_id, logged_at DESC);
CREATE INDEX idx_audit_event_type ON audit_events(event_type);
```

## 4. State Machine Lifecycle Rules

The system enforces strict operational state transitions across the procurement workflow:

1.  **Parsing to Discovery**: An `order_intent` enters `PARSED` state upon NLP parsing and transitions to `SEARCHING` when querying merchant MCP/JSON-LD feeds.
2.  **Match Evaluation**: Once product candidates are aggregated, state advances to `MATCHED` and immediately triggers `GOVERNANCE_CHECK`.
3.  **Governance Resolution**:
    *   *Path A (Compliant)*: If item price <= `max_item_price_cap` AND cumulative daily spend + item price <= `daily_spend_cap`, status updates to `GOVERNANCE_PASSED` and triggers `TOKEN_REQUESTED`.
    *   *Path B (Policy Exception)*: If spend caps or escalation thresholds are breached, status transitions to `HITL_PENDING` and locks further automated execution.
4.  **Human Resolution**:
    *   Upon user approval, status transitions to `HITL_APPROVED` -> `TOKEN_REQUESTED`.
    *   Upon user rejection or 15-minute expiration, status transitions to `GOVERNANCE_BLOCKED` and releases execution locks.
5.  **Tokenization and Native Execution**: `TOKEN_REQUESTED` advances to `TOKEN_ISSUED` when PayPal Agent Ready returns a scoped token hash, moving to `CHECKOUT_SUBMITTED` upon posting payloads to merchant APIs. Final resolution yields `COMPLETED` or `FAILED`.

## 5. In-Memory Cache Key Specifications (Redis 7.2)

To deliver sub-second governance evaluation and prevent double-spending concurrency bugs, Redis key patterns are structured as follows:

| Key Pattern Structure | Redis Data Type | TTL (Seconds) | Operational Purpose |
| ------ | ------ | ------ | ------ |
| `user:spend:daily:{user_id}:{YYYY-MM-DD}` | String (Decimal Counter) | 86,400s (24h) | Atomic increment counter (`INCRBYFLOAT`) for real-time daily cumulative spend. |
| `lock:checkout:{user_id}` | String (Mutex Token) | 30s | Distributed Redlock preventing concurrent checkout execution per user. |
| `hitl:session:{escalation_id}` | Hash | 900s (15m) | Active Human-in-the-Loop session state, token hash, and product details. |
| `merchant:mcp:session:{merchant_id}` | String (Bearer Token) | 3,600s (1h) | Cached session bearer token for authenticated merchant MCP servers. |

## 7. Security, Privacy, and Data Retention Protocols

1.  **Zero Raw Credential Storage**: Primary Account Numbers (PAN), CVVs, and raw payment card credentials are strictly excluded from the background schema.
2.  **Encryption at Rest**: Sensitive user profile fields (`email`, `full_name`) are encrypted using AES-256-GCM prior to database insertion.
3.  **Token Anonymization**: Payment tokens issued by PayPal Agent Ready are stored solely as SHA-256 reference hashes in `payment_tokens.payment_token_ref_hash`.
4.  **Data Retention & Compliance Purging**: Financial transaction logs and audit event ledgers are retained for 7 years to meet accounting standards. Raw natural-language prompt strings are anonymized after 90 days.
